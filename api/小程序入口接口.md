# 均州点餐餐饮系统：小程序后端入口

后端提供商家发现、无选店的个人资料/地址、当前商家本人订单及扫码解析入口。配套小程序已升级 Vue 3 + Pinia，并完成商家选择及四栏页面，运行方式见 [小程序说明](../weixin-uniapp/README.md)。

## 发布前置

已有业务库先按 [迁移说明](../database/migrations/README.md) 执行 `20261112_01_merchant_discovery.sql`，再发布后端。该迁移只增加 `tenant.logo_url`、`tenant.introduction`、`store_settings.contact_phone` 三个可空字段，不更改租户/门店归属。使用全量初始化 SQL 新建库后也要追加该迁移。

## 身份和数据范围

| 请求 | authentication | X-Store-Id | 数据范围 |
| --- | --- | --- | --- |
| 商家、门店发现 | 不需要 | 不需要 | 公开展示信息，启用商家及门店 |
| `/user/me`、本人订单、地址簿 | 必须 | 不需要 | 当前登录用户；订单额外限定必填 merchantId |
| 桌码解析 resolve | 必须 | 不需要 | 有效随机桌码的公开归属，不加入桌次 |
| 菜单、营业信息旧接口 | 不需要 | 必须 | 有效门店所属租户 |
| 购物车、报价、下单、支付、入桌 join | 必须 | 必须 | 当前用户 + 服务端验证的租户和门店 |

同一用户在不同商家共用地址簿，下单按目标门店重新校验配送范围。订单页仅显示本人在当前商家的订单，不传门店时展示该商家全部门店；不能省略商家查询全平台订单。订单列表的门店筛选不修改点单上下文。

服务端从有效门店推导租户，不信任客户端 tenantId。没有门店不会自动使用门店 1。商家和门店切换不重新注册用户、不删除原店购物车，也不改变历史订单归属。

## 新增接口

| 方法和路径 | 参数 | 说明 |
| --- | --- | --- |
| GET `/user/merchants` | keyword?, page?, pageSize? | 商家目录与名称搜索 |
| GET `/user/merchants/{merchantId}` | 路径 ID | 确认商家可用、恢复上次选择 |
| GET `/user/merchants/{merchantId}/stores` | keyword?, page?, pageSize? | 指定商家可用门店，支持分页 |
| GET `/user/stores/{storeId}/context` | 路径 ID | 门店公开信息、营业状态、费用、配置版本 |
| GET `/user/me` | 无 | 本人的 userId、nickname、avatarUrl，不返回 openid |
| GET `/user/me/orders` | **merchantId**；storeId?, status?, refundOnly?, page?, pageSize? | 当前商家本人订单 |
| GET `/user/me/orders/{orderId}` | **merchantId**；路径订单 ID | 本人只读历史详情，不返回核销/支付凭据 |
| GET `/user/me/order-filters` | **merchantId** | 本人订单涉及的该商家门店，包含历史停用门店 |

分页默认 page=1、pageSize=10，pageSize 最大50；商家/门店按ID升序，订单按下单时间、ID降序。keyword 首尾去空白、最多100字符，`%`、`_` 按文字匹配。status 沿用1..6；退款筛选 `refundOnly=true` 包含退款中、已退款及退款异常，与 status 同传取交集。

商家详情：merchantId、merchantName、logoUrl、introduction、activeStoreCount。目录只包含启用且至少有一家启用门店的商家，营业休息不等于停用。门店 `open=false` 时仍可展示，但不能据此绕过原有下单营业检查。

门店 context 返回 merchantId/merchantName、storeId/storeName、logoUrl、地址/联系电话、坐标、营业时间、费用、配送半径和 configVersion。坐标系统明确为 BD09；微信定位坐标不能直接当作同一坐标系使用。logoUrl 无公开素材时为 null；当前仅接受无签名参数、无用户凭据的 HTTPS `/public/` 静态图片路径，不能填写员工鉴权文件接口。

新接口 ID 为字符串，金额为两位小数的元字符串，时间为 Asia/Shanghai 的 `yyyy-MM-dd HH:mm:ss`。原有业务接口和扫码兼容字段的类型保持原协议。

## 响应与失败

成功沿用 `{ "code": 1, "msg": null, "data": ... }`；分页 data 为 `{ "total": 0, "records": [] }`。新入口失败返回 `{ "code": 0, "msg": "错误说明", "data": null }`。

新入口参数错误 HTTP400、未登录401、不可读资源404、依赖失败503。原有门店接口仍保留原业务失败协议，调用方同时检查 HTTP 状态和 code。

例如（以下仅为请求格式示例）：

```http
GET /user/me/orders?merchantId=1&page=1&pageSize=10
authentication: <微信登录获得的 token>
```

将 storeId 加入查询可以缩小到该商家的一家门店。错商家的 storeId 返回400；订单不属于本人或指定商家时返回404。传入 userId 不会改变查询身份。

历史订单名称和金额优先读取冻结快照，旧快照回退原历史明细/金额，不按当前菜价重算。商家/门店停用后本人历史仍可读；storeAvailable=false 时不能用这些只读入口执行支付、催单或重购。新订单快照追加商家ID和名称，不批量改写旧订单。

## 沿用并调整的入口

- POST `/user/user/login` 保持微信 code 登录与旧响应，不要求先选店。
- `/user/addressBook/**` 保持原路径和增改删载荷，改为无选店也可使用；只能读取和修改本人地址。
- POST `/user/dining/resolve` 接受 `{ "token": "32位随机桌码" }`，需登录，不要求选店。保留旧 id/name/tenantId/storeId 类型，新增 merchantId/merchantName；不返回当前桌次、成员或原始桌码。
- POST `/user/dining/join` 仍需目标 X-Store-Id 和登录。解析结果只用于定位；入桌和提交订单再次核验归属、桌码及桌次。保留旧客户端所需 currentSessionId，不返回 qrToken。
- 旧 GET `/user/stores` 仍按当前门店推导的租户查询，不能当作平台商家目录。

从订单页支付、取消、催单或重购时，先验证并切换到该订单原门店，再调用原 `/user/order/**` 接口。重购追加到原店购物车，不先清空。提交结果未知时保留原请求号、原门店与载荷，通过显式重试恢复；不可将网络失败当作未生成订单。


```powershell
python scripts/test-merchant-discovery-migration.py
```
