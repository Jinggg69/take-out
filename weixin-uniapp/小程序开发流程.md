# 小程序开发与联调流程

本工程已升级 Vue 3 + Pinia，默认启动商家选择页，进入门店后使用首页、点单、订单、我的四个原生tab。

1. 按根目录说明启动后端与Redis，执行所需增量迁移，特别是商家发现字段迁移 `20261112_01_merchant_discovery.sql`。
2. 在本目录执行 `npm ci`，核对 `manifest.json` 微信AppID及 `utils/env.js` 后端地址。
3. 执行 `npm run dev:mp-weixin`，微信开发者工具导入 `unpackage/dist/dev/mp-weixin`；或使用具备Vue3编译插件的HBuilderX导入源码目录后运行。
4. 微信开发者工具如需由HBuilderX唤起，开启服务端口，并在HBuilderX配置开发者工具安装路径。
5. 正式产物执行 `npm run build:mp-weixin`，导入 `unpackage/dist/build/mp-weixin`。

`npm run check` 验证所有行为回归及微信/H5编译；`node scripts/check-mp-artifact.mjs` 验证产物入口、tabBar和主包预算；`npm run test:ui` 使用本机Chrome测试独立界面数据，不能替代真实后端/微信能力联调。

联调依次覆盖：匿名商家搜索、单/多门店、继续上次选择、扫码入桌、三种履约、规格购物车、地址、报价、支付、本人商家订单筛选与详情。必须使用至少两个商家及两个用户，确认切换后不串商品、购物车、订单或桌次。

故障分支需覆盖：商家停用、无门店、网络失败、401、报价变化、提交响应丢失、支付通知延迟、冷启动恢复，以及其他用户重新登录。地址请求失败应释放加载遮罩；未知提交和支付不得自动重放到其他门店。

原用户端接口路径和 `authentication` 请求头沿用。新增公开/身份入口不发送 `X-Store-Id`；门店业务必须发送该头。只读历史详情不泄露取餐凭据，也不修改真实购物车。

真机不能访问开发电脑的 `localhost`，请改为可达地址；发布前设置合法请求域名、微信商户及通知地址，核验真实微信登录、支付和退款。平台名称为均州点餐餐饮系统，均州鱼庄仅作为其中一个商家。
