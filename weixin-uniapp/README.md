# 均州点餐餐饮系统 · 微信小程序

基于 **uni-app、Vue 3.4.21、Pinia 2.2.0** 的多商家餐饮用户端。页面使用真实后端数据，没有固定餐厅品牌或内置商家演示数据。

## 入口与四栏

- 首次进入选择商家；单门店直接进入，多门店继续选择。上次选择须重新向后端验证，可继续访问或重新选择。
- 首页：当前商家与门店、营业和费用信息、堂食扫码、自取、外卖入口。
- 点单：分类与菜品、套餐、规格选择、独立门店购物车及结算。
- 订单：本人在当前商家的订单，可按该商家的门店和订单状态筛选。门店筛选不改变当前点单门店。
- 我的：平台用户信息、共用收货地址、当前门店与联系方式。

地址、结算、支付、订单详情保留为二级页面。有效桌码可定位门店并加入桌次；商家/门店参数支持冷启动及再次进入。微信小程序码制作和发布配置仍按实际微信平台配置处理。

## 本地运行

CLI 使用 Node.js 22.18 或更新版本：

```powershell
cd D:\take-out\weixin-uniapp
npm ci
npm run dev:mp-weixin
```

微信开发者工具导入 `unpackage/dist/dev/mp-weixin`。正式编译：

```powershell
npm run build:mp-weixin
node scripts/check-mp-artifact.mjs
```

正式产物位于 `unpackage/dist/build/mp-weixin`，可直接导入微信开发者工具。检查脚本核对商家入口、四栏页面、图标及2 MiB主包预算。旧版大品牌图保留在 `design/legacy`，不进入运行包。

也可使用 HBuilderX 导入本目录，`manifest.json` 已指定 Vue 3。若当前 HBuilderX 尚无 Vue 3 编译器，按 IDE 提示安装对应编译插件；npm CLI 使用锁定的独立编译器，不依赖该插件是否安装。

若出现 `Cannot find module .../uni_helpers/lib/bytenode`，检查 HBuilderX 的 `plugins/uni_helpers` 目录：这是 IDE 编译插件依赖缺失。通过“工具 → 插件安装”补装或修复 uni-app 编译器及其依赖后重新运行；仅安装项目的 npm 依赖不能补齐这个 IDE 插件。2026-11-12 已使用本机缓存中与 5.26 官方插件清单校验值一致的安装包补齐该目录，并通过 HBuilderX 自带 Node.js 与 5.26 Vue 3 编译器的微信构建验证。

H5 用于界面开发和验证：

```powershell
npm run dev:h5
npm run build:h5
```

微信 code 登录和原生微信支付应在微信开发者工具、真机中验证，H5不能代替原生微信能力验收。

## 后端与配置

接口协议见 [小程序入口接口](../api/小程序入口接口.md)。先发布第二步后端，并按 [数据库迁移说明](../database/migrations/README.md) 执行 `20261112_01_merchant_discovery.sql`，再运行本小程序。

- `utils/env.js` 默认 `http://localhost:8080`；真机需改成设备可访问的服务地址，发布时配置微信合法请求域名。
- 保留现有 `manifest.json` AppID；请使用自己有权限的微信应用。
- `public` 请求不带登录或门店，`identity` 请求带用户认证，`store` 请求必须有服务端验证过的门店。未选店不会回退到ID1。
- Pinia使用实际 actions 和状态，不保留 Vuex 的 `commit/state` 兼容层。`$appStore` 是注入交易 Options API 页面的真实 Pinia 实例。

## 交易与恢复

结算依赖服务端报价；报价失败不能下单，金额变化后需显式确认。堂食、自取、外卖分别使用后端履约费用；前端购物车金额仅用于浏览，最终费用以报价为准。

提交携带 `clientRequestId`；结果未知时按用户保存原门店、请求号与载荷，只允许显式重试原意图。支付未确认时保留原门店锁与查单恢复信息；隐藏页面、冷启动、切换用户都不能把原意图用于另一商家或另一用户。确认终态后解除锁。

历史订单使用冻结名称和金额；详情不会覆盖购物车。查看其他门店的本人订单不自动切换购物车，执行支付、取消或重购前重新验证原门店。停用门店订单只读。后端指定 `MOCK` 时显示学习演示收银台；实际微信渠道继续调用原生支付，不以界面按钮代替后端确认。
