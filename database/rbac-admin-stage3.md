# 阶段 3.4：管理端角色任职与门店切换

## 使用流程

登录后先从 `GET /admin/rbac/context` 读取当前员工真实可访问门店和每个门店的有效动作权限。该接口只要求已认证员工身份，不依赖所选门店，不接受前端指定员工或租户；无门店授权时仍可改密/退出并显示联系管理员的空状态。加载失败可重试。门店及员工等 bigint 标识在新读接口中由服务端返回字符串，避免浏览器损失大整数精度。

顶部门店选择器只列出当前员工允许的门店。初次登录默认选择第一家可访问门店；本版本不持久化上次门店，重新登录后重新核验。所有后续管理端请求附带 X-Store-Id。导航按当前门店实际权限显示，直达未授权页面显示无权限提示。退出、改密不要求店铺动作；营业状态与设置按 shop:read/shop:update 展示。订单操作、报表导出及员工新增/修改/启停按钮也按相应动作权限展示。其他业务写入口继续由阶段 3.3 后端强制鉴权。

商户管理员可从“角色与任职”进入：

- **角色权限**：选择已有角色，勾选具体操作并整体保存。界面按资源分组显示中文动作及精确权限 code，不自动扩展权限。此步骤配置已有固定角色及数据库内已有角色，不增加角色创建/删除接口。
- **员工门店任职**：选择启用员工，添加/移除角色，为每个角色分别选择本店、指定门店或本商户全部门店，并选择角色任职门店。本店/指定店清单为空时不会获得门店权限；全部店包含以后新增的本租户有效门店。保存空任职列表表示撤销该员工全部授权。

配置使用 `GET /admin/rbac/configuration`，后端要求具有 TENANT_STORES 范围的 employee:manage，仅返回当前租户的角色、权限、员工简要信息、有效门店和任职关系，不返回密码。保存复用 3.3 两个整体替换接口和最后管理员保护。保存前明确提示将撤销本商户所有管理端会话；成功后清除本地会话和门店状态并返回登录页。保存失败保留编辑内容。重复角色在前端拒绝；跨租户门店、最后管理员保护等继续由后端校验。

## 切店隔离机制

门店切换先提示清空未保存内容。只在路由导航未被取消且没有在途写请求时切换，避免卸载正在保存的表单；目标页面移除旧查询参数（如订单 ID、编辑 ID）。被取消的导航保持原门店；同一路由的重复导航允许切店。

每次切店增加 revision，即使 A→B→A，版本也不同。业务工作区以 revision 为 key 重建，列表筛选、分页、详情、表单草稿、对话框和页面内缓存重新初始化；保留应用原有样式及侧栏行为。前端没有按门店持久化草稿/列表缓存。本步骤明确选择清空草稿，提示后再切换。

HTTP 请求保存发送时的门店版本与 token；成功响应和错误响应到达时都先比较当前身份版本。旧版本被取消错误拒绝，不能回写当前页面；旧请求的 401 不会清除新会话。去重键包含 token、门店和版本，同样的接口参数在两个门店不互相阻塞。全部写请求计数驱动切店禁用状态，重复请求取消不会错误减少其他请求计数。

订单提醒随工作区卸载关闭旧 WebSocket、移除监听、关闭旧通知并暂停声音；新连接查询参数携带经过后端核验的 storeId，token 仍使用协议头。排队到达的旧消息和错误回调也比较 revision，避免切店瞬间旧通知弹出；没有 order:read 时不建立订阅。服务端仍在握手和推送前重新检查会话及权限。
