# 阶段 2.5：文件归属与管理端访问

2026-11-03，基于 HEAD `bd9f37d` 的工作区增量。

## 交付范围

- 上传只接受公开菜单 PNG/JPEG：限制小于 2MB、至多 1600 万像素；使用实际内容识别格式，解码后重编码，忽略客户端文件名、扩展名和 MIME 声明。私有附件不在本接口用途内。
- `file_asset` 保存 UUID、可信租户、上传员工、固定用途 `PUBLIC_CATALOG`、对象键、公开 URL 和时间。租户有外键且无默认值；对象键和 URL 唯一。插入时再次核验员工所属租户和启用状态。
- 对象键为 `tenants/{tenantId}/public-catalog/{uuid}.png` 或 `.jpg`，不接受客户端路径；上传失败或数据库登记失败时尝试删除这一个新生成的对象，失败只记录对象键供排查，不返回未登记 URL。
- `POST /admin/common/upload` 继续返回 `Result<String>`，管理端无需改变上传调用。
- 新增 `GET /admin/common/file?url=...` 查询当前租户的公开菜单文件元数据。未知、旧未登记、其他租户 URL 均拒绝，缺少员工身份、有效门店权限或作用域也拒绝。
- 菜品、套餐新增及修改均在业务服务内校验新图片引用。同租户的其他授权门店可引用租户目录图片；不能借用其他租户文件 URL、任意外部 URL 或未登记旧 URL。

## 历史兼容与发布

商品原有图片 URL 不变时可继续保存，避免改价等操作强迫历史图片重传。该兼容只作用于当前已授权商品已有的 URL；新增商品或更换图片不会自动认领旧链接。没有自动以租户 1 回填的脚本。

新增 `20261103_01_file_asset.sql` 并同步初始化定义。先迁移再部署；未执行真实业务库迁移，未触及真实 OSS 对象及权限。公开图片可通过其 URL 被读取，隔离约束针对管理端元数据与业务引用；不宣称公开图片具有保密性。历史盘点、共享 URL 处理及 OSS 访问策略详见 [迁移说明](migrations/README.md)。

上传与元数据登记之间不使用跨 OSS/数据库的分布式事务。补偿删除失败时，新对象可能成为无业务引用的公开图片，应用会记录该对象键；部署负责人应按日志与元数据核对孤立对象。进程在写入后崩溃也需按此方式清理。代码不自动删除历史对象。
