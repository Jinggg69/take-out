# 阶段 2.4：数据库访问归属约束

本项保留阶段 2.3 的单店保护，缓存、消息及多支付配置隔离仍依赖 2.5—2.7。SQL 的范围来自服务端 RequestScope，不从 DTO 或任意租户头取值。缺少必要范围时拒绝执行，不回落到默认租户。

## Mapper 核对清单

| Mapper（含同名 XML） | 数据边界 |
| --- | --- |
| CategoryMapper | 租户分类的列表、分页、新增、更新、删除；显式归属参数须匹配可信上下文 |
| DishMapper、DishFlavorMapper | 租户菜品和同租户分类；口味经父菜品限制；混合无权 ID 批量操作不能部分成功 |
| SetmealMapper、SetmealDishMapper | 租户套餐、分类和组成菜品必须一致；关联查询和批量写入受父记录约束 |
| EmployeeMapper | 管理端员工操作限定租户，新建显式设置归属；登录凭据校验为独立引导入口 |
| AdminSessionMapper | 会话从员工继承租户；撤销受租户限制；签发及验签按精确会话/员工处理 |
| UserMapper | 顾客资料与锁定仅本人；支付只经授权订单读取必要 id/openid |
| AddressBookMapper | 地址新增、查询、修改、删除均限当前顾客；商家不能直接访问顾客地址簿 |
| ShoppingCartMapper | 所有读取、增减、合并、刷新及删除均限制租户、门店、用户；插入显式设置三者并验证商品同租户 |
| OrderMapper | 订单列表、详情、锁定、统计、状态修改和幂等查找限制租户、门店，顾客请求另限本人；插入验证门店和本人地址 |
| OrderDetailMapper | 通过已授权订单读取历史快照；写入验证商品与订单归属并核对完整写入结果 |
| RefundRequestMapper | 退款查找、任务领取、写入及更新均经已授权父订单，写入检查原单号与金额 |
| OrderMaintenanceMapper | 状态更新限定租户、门店及有效门店父关系，保留原支付状态和时间条件 |
| TenantScopeMapper | 认证范围引导：读取有效员工/门店归属及单店保护状态，不提供普通业务数据访问 |

## 无请求上下文的明确入口

登录时还没有请求范围。EmployeeMapper 的全局唯一用户名查找与带密码复核的签发查询只供认证使用；会话创建使用已锁定员工记录中的租户。UserMapper 的 openid 查找及注册只接受微信服务验证得到的身份。它们不能作为普通业务缺上下文时的通用降级路径。

支付回调和定时任务采用受控的 LegacySystemScope：已验证回调或后台任务入口先核验整个数据库仍只有启用的默认租户/门店，再显式建立系统范围；SQL 仍带租户/门店条件，退出时恢复或清理范围。增加任何租户或门店时该桥接入口拒绝运行。以后 2.5/2.6 实现逐订单定位与支付配置路由时替换该过渡桥接，不得删除 SQL 范围条件。

## 发布边界

本项沿用已有归属列，无新增业务 schema 迁移；部署前须完成 tenant/store 迁移及前置步骤。不能仅凭本项 SQL 检查通过开放第二个真实商户或门店。现有缓存键、WebSocket、文件和支付配置路由仍按后续阶段推进。
