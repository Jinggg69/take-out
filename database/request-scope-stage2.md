# 阶段 2.3：可信请求上下文与单店过渡

2026-11-02，基于 677dc4d。后端建立不可变请求上下文，包含员工或用户 ID、租户 ID、门店 ID、员工允许门店集合；JWT 不提供租户权限。管理端先验证会话及员工状态，再从员工记录读取有效租户；员工当前只可访问其租户唯一启用的门店，提供的 X-Store-Id 如不匹配则拒绝。不存在唯一门店时拒绝。可配置任职和跨店授权属于阶段 3。

用户请求通过必需的 X-Store-Id 选择门店，服务端查找有效门店与有效租户，从门店推导租户，不读取 X-Tenant-Id。匿名分类、菜品、套餐、营业状态等也执行门店验证；订单、购物车和地址簿仍要求用户 JWT。登录与支付回调不使用该请求拦截器。小程序暂时固定传入门店 1，后续选店功能替换此值。管理端在此阶段可省略门店头，服务端只在唯一有效门店可确定时推导；伪造的门店头会被拒绝。

**单店保护：** 由于 SQL、缓存、消息和支付隔离尚未完成，拦截器要求数据库中恰有一个租户及一个门店，且两者均启用、ID 为 1 且归属一致。多出任何租户或门店（包括停用记录）时拒绝受保护的业务请求。此保护不能代替 2.4—2.7 的隔离改造；不要创建第二个真实商户或门店。单店保护仅覆盖普通 HTTP 业务入口，后台扫描和支付回调仍是单店实现，不得对多租户库运行。

上下文为普通 ThreadLocal，不自动传播到线程池；拦截器在请求开始、完成及异步交接时清理，认证失败时同样清理。定时任务入口和 finally 清理身份与作用域；当前没有应用自建的异步线程池，未来异步工作必须显式携带可信范围并在 finally 清理。后台任务尚未按订单装载范围，其隔离实现属于 2.5/2.6。

## 部署与回退

先完成 `20261029_01_tenant_store.sql` 及其前置迁移并确认默认租户、门店和历史员工归属，再部署后端和包含门店头的小程序。阶段 2.3 不新增数据库迁移；缺失租户表或数据库不可用时业务请求返回 503。用户请求缺少或伪造门店头返回 403；发布时须同步客户端，旧客户端没有该头，用户端业务请求会被拒绝。管理端授权失败返回 403；认证失败仍为 401。若需回退，应同时恢复对应客户端与后端；继续保留新增数据库字段。回退只适用于尚未创建多租户数据的单店环境。
