# 隔离验收数据（2026-11-02 阶段一）

`saas-isolation.json` 是独立、固定、完全合成的测试数据，不是生产种子或数据库迁移。包括商户 A/B、A1/A2/B1 三门店、4 员工、3 用户、4 订单及明细，使用虚构名称、无效微信标识，没有电话、地址、密钥或可登录密码。

从仓库根目录运行 `python scripts/test-saas-fixture.py` 校验唯一性、父子归属、金额、员工范围及正反访问矩阵，不连接数据库。

## 数据契约

- ID 与默认商户/门店 1 分开；不保证与任意业务库 ID 不冲突，只允许后续测试装载到新建临时库。
- `employees.allowed_store_ids` 是未来授权测试的期望输入，当前数据库尚无员工任职关系表，不能认为当前服务已经执行这些授权。
- 用户是全局身份，无 `tenant_id`；3103 在 A2 和 B1 都有订单，用于验证商户不能因共享用户而看到其他租户订单。
- 订单金额以元字符串表示；详情 `unit_price` 对应现有 `order_detail.amount`，`quantity` 对应 `number`。明细仅通过 `order_id` 继承归属。
- 订单统一为已完成、已支付的合成快照；没有真实微信交易号，不用于支付/退款/报表口径验收。
- `access_expectations` 是阶段二后端读取、修改、删除授权测试的期望，不是已通过的服务端隔离测试。

后续阶段的测试适配器可直接读取 JSON，按真实 schema 显式插入租户、门店、员工、用户、订单和明细，并映射字段名。任职关系、登录密码和必填业务快照由对应阶段在临时环境补齐。禁止将本文件直接导入正在运行单店任务的数据库；当前应用尚未隔离。本阶段不新增 schema，不执行真实业务库迁移。
