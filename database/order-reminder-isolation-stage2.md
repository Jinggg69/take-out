# 阶段 2.5：订单提醒隔离

2026-11-03，基于 HEAD `e1222b6` 的工作区增量。完成 WebSocket 认证、门店订阅与订单提醒路由；2.5 的后台任务及文件归属仍待完成，保留单店保护。

## 行为

- `/ws/{clientId}` 改由 Spring WebSocket 管理，移除无认证的 JSR-356 端点和全局广播。连接 ID 只表示客户端连接，不用于授权或覆盖其他连接。
- 握手通过 `Sec-WebSocket-Protocol` 提供 `junzhou-orders` 与 `auth.<管理端JWT>`；令牌不进入 URL。服务端验证 JWT 签名、有效期、员工会话及当前员工/租户/门店状态，执行现有单店保护。认证失败拒绝握手，不允许匿名订阅。
- 可选 `storeId` 查询参数仅为待验证选择；租户从员工归属推导，不接受客户端声明的租户。未传门店时沿用当前唯一有效门店解析规则；多店任职配置仍属于阶段 3。
- 会话绑定握手核验的租户与门店。每次发送前重新验证令牌、会话和当前授权，撤销、过期、停职、门店或租户失效、归属变化均使连接关闭；存储不可用时拒绝投递。无事件的空闲连接在下一次发送时执行复核，不承诺立即物理断开。
- 连接表使用并发映射，以服务端 WebSocket 会话 ID 标识连接；发送串行化，关闭及发送失败时移除连接；客户端消息不能修改订阅范围。
- 支付成功提醒继续只在事务提交后发送一次，目的租户、门店来自订单记录。订单实体补充已有数据库归属字段，无新增 schema；事务回滚和重复支付不发送额外提醒。
- 用户催单 HTTP 接口接入已有业务，查询仍受本人、租户、门店 SQL 约束，再按订单归属发送。其他用户或其他门店订单不能产生提醒。
- 管理端提供认证子协议；开发环境改用同源 `/ws/` 代理，保留默认同源 Origin 校验。生产继续使用同源代理；反向代理须保留原始 Host、WebSocket Upgrade 和子协议头；开发代理仅对 WebSocket 关闭 changeOrigin，以保持 Host 和浏览器 Origin 一致。前后端必须配套发布，旧匿名客户端将不能连接。
